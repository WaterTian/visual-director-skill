# Visual Brief / 视觉需求单

Use a Visual Brief when a request has several constraints, will be repeated, or must enter a product asset pipeline. / 当需求包含多个约束、需要重复生成或进入产品资产流程时使用。

Capture only decision-relevant information: / 只记录影响决策的信息：

- Goal and audience / 目标与受众
- Deliverable type, dimensions, ratio, format, and transparency / 类型、尺寸、比例、格式和透明度
- Subject, supporting elements, and exact visible text / 主体、辅助元素和逐字可见文字
- Composition, camera, hierarchy, lighting, materials, palette, and finish / 构图、相机、层级、光线、材质、色板和完成度
- Brand rules and product facts / 品牌规则与产品事实
- Reference image role: identity, composition, style, palette, or material / 参考图角色：身份、构图、风格、色板或材质
- Must-include, must-avoid, and acceptance criteria / 必需项、禁止项与验收标准
- Candidate and formal output paths when files will be saved / 需要落盘时记录候选与正式路径

Do not invent product facts or brand rules. Reversible aesthetic choices may be labeled assumptions. Ask only when two plausible choices would produce materially different assets. / 不虚构产品事实或品牌规则；可逆审美选择可作为明确假设。只有不同选择会显著改变结果时才询问。

The machine-readable contract is `schemas/visual-brief.schema.json`. / 机器可读契约见该 schema。
